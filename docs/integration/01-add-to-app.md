# 1 · Add to your app

[Integration guide](README.md) · next: [Launch and exit](02-launch-and-exit.md)

Result: the onboarding activity compiles inside your app module and opens with `adb`, its resources prefixed so nothing clashes with yours.

| | This demo | Notes |

| minSdk | 28 | Tested only on API 28+. If your app's minSdk is lower, open the onboarding only on API 28+ until it is audited ([Launch and exit](02-launch-and-exit.md#first-run)). |

## 1. Copy the code

| From `app-views/src/main/java/namvunhatle/r15/onboarding/` | To your app | Contents |
| --- | --- | --- |
| `core/` (18 files) | `<your.package>.onboarding.a7.core` | Engine, script, art, audio, tokens |
| `views/MainActivity.kt` | `<your.package>.onboarding.a7.A7OnboardingActivity` | The activity (rename the class) |
| `views/Widgets.kt` | `<your.package>.onboarding.a7` | Custom views used by the XML layouts |

- Move the packages with **Refactor → Move** in Android Studio. It also rewrites the custom-view class names in the XML layouts (`namvunhatle.r15.onboarding.views.CssBox`, and so on).
- `A7Art.kt` and `A7Native.kt` import `namvunhatle.r15.onboarding.views.R`. Point them at your app's `R`.
- Keep `core/` whole: its files depend on each other.

## 2. Copy the resources, with a prefix

Resource names share one namespace with your app. If a name exists on both sides, one file silently wins and the onboarding (or your app) draws the wrong thing. Copy each folder below, then rename every resource that does not already start with `a7_`, `zen_` or `adkit_`.

| Type | Names in the demo | Rename to | Why it clashes |
| --- | --- | --- | --- |
| Layout | `activity_main`, `native_ad`, `bubble`, `lyric_card` | `a7_onboarding`, `a7_native_ad`, `a7_bubble`, `a7_lyric_card` | `activity_main` and `native_ad` almost certainly exist in your app |
| Drawable (XML) | `ad_badge`, `chip`, `fab`, `flash`, `pill`, `punch`, `tag` | `a7_…` | Generic names |
| Drawable (bitmaps, `drawable-nodpi/`) | `logo_src`, `screen_g01`–`03`, `splash_base`, `splash_wisps` | `a7_…` | Generic names |
| Font | `anton_regular`, `bevietnampro_regular` / `_medium` / `_semibold` | `a7_…`, or reuse yours if the files are identical | Anton is not part of the ZEN design system: it adds about 170 KB |
| Style | `T`, `T.W400`, `T.W500`, `T.W600`, `T.Lyric`, `T.Line`, `T.Meta`, `T.Bubble` | `A7Text`, `A7Text.W400`, … | One-letter name |
| Theme | `A7` (`values/` and `values-v31/`) | `Theme.A7Onboarding` | Generic name |
| Attribute (`attrs.xml`) | `fill`, `fill2`, `fillAngle`, `fillStop0`, `fillStop1`, `cornerRadius`, `strokeColor`, `strokeWidth`, `shadowY`, `shadowBlur`, `shadowColor`, `ringStroke`, `ringAlpha` | `a7_fill`, … | Material Components also defines `cornerRadius`, `strokeColor` and `strokeWidth` |

Do not copy the mock-only resources: they are replaced in later steps. They are `dest_ai`, `dest_home`, `dest_paywall`, `inter_fill`, `ic_a7_launcher`, `ic_replay`, `ic_sb_battery`, `ic_sb_signal`, `ic_sb_wifi` and `mona_sans_medium`. The code that uses them is listed in [Before release](07-before-release.md). Until you have removed that code, copy them too, so the project compiles.

**How.** Use **Refactor → Rename** on each resource: it updates `R.layout.…`, `R.drawable.…`, `R.font.…`, `R.styleable.CssBox_…` in Kotlin and every `@drawable/…`, `@style/…`, `app:…` reference in XML.

**Tokens already prefixed.** `values/zen_tokens.xml` (`zen_*`, `adkit_*`, `project_*`, `aosp_*`) and `values/a7_visual.xml` (`a7_*`) keep their names. If your app already defines `zen_*` resources, compare the values before merging. This demo resolves ZEN in the modes **Light · Global - Base 14 · Brand Emphasis - S1 · Base Colors Zen**. The same name with a different value means one of the two silently wins.

**Layout generator.** `activity_main.xml` is generated by `tools/gen_layout.py` from `assets/manifest.json`. The script hard-codes resource names and class names. After the renames, either update the script or stop using it and edit the layout by hand.

## 3. Move the assets into a folder

`assets/` is also one namespace. Move the demo's files under `assets/a7/`:

| Asset | Size | Read by |
| --- | --- | --- |
| `manifest.json` | 14 KB | `Scene` constructor: `ctx.assets.open("manifest.json")` |
| `tracks.json` | < 1 KB | `Scene` constructor: `ctx.assets.open("tracks.json")` |
| `audio/future-pop_intro.ogg`, `audio/future-pop_loop.ogg` | 330 KB | `A7Audio.prepare`: `"audio/${tr.id}_$part.ogg"` |

Then add the `a7/` prefix to those three paths.

## 4. Declare the activity

```xml
<activity
    android:name=".onboarding.a7.A7OnboardingActivity"
    android:exported="false"
    android:theme="@style/Theme.A7Onboarding"
    android:screenOrientation="portrait"
    android:configChanges="orientation|screenSize|screenLayout|keyboardHidden|uiMode" />
```

- No launcher intent filter: your app opens it ([Launch and exit](02-launch-and-exit.md)).
- Do not copy the demo manifest's `<application>` label and icon.
- `configChanges` stops the activity from being recreated mid-trailer. Recreation would restart the timeline and re-bake the art.
- The theme's window background, `#262551`, is the splash's corner colour. It shows while the activity starts, before the first frame, so keep it.

## 5. Build type

- Ship an **R8-minified release build**. A debuggable build opens about 3× slower ([Performance](06-performance.md)).
- No extra ProGuard/R8 rules are needed. The demo's v1.3.7 release is minified. Custom views are kept through their layout references, and the JSON is read with `org.json`, without reflection.

## 6. Check

The shell cannot start a non-exported activity. Export it in debug builds only, so `adb` and the [acceptance checks](08-acceptance.md) can open it directly:

```xml
<!-- src/debug/AndroidManifest.xml -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <application>
        <activity
            android:name="<your.package>.onboarding.a7.A7OnboardingActivity"
            android:exported="true"
            tools:replace="android:exported" />
    </application>
</manifest>
```

```sh
adb shell am start -n <your.app.id>/<your.package>.onboarding.a7.A7OnboardingActivity
```

The trailer should play exactly like the [v1.3.7-merge-module](https://github.com/namvunhatle/r15-onboarding-android-demo/releases/tag/v1.3.7-merge-module) APK. The mocks are still in place at this point. [Acceptance checks](08-acceptance.md) has a frame-by-frame comparison.
